# SnipWar Agent Notes

## Godot checks
- Godot is not on PATH; run headless commands via the console binary, set `GODOT_BIN` to it (or put `godot` on PATH).
- `--headless --path . --quit-after 2` = main-scene smoke test; `--headless --path . --script res://scripts/preflight.gd` = persistent test suite (no GUT). Temp lifecycle checks use `res://.tmp_*.gd` and must be removed, including the generated `.tmp_*.gd.uid` sidecar.
- Headless uses the Dummy renderer, so `Window.get_texture()` is null; visual captures need the desktop Compatibility/OpenGL renderer, and `Window.size` must be set again after scene init (the window override otherwise keeps the first 960×540 capture at the physical size).
- A headless editor scan can exit 0 despite an `EditorFileServer` port-6010 conflict aborting its scan thread; trust runtime preflight + smoke test. Render-budget assertions estimate CanvasItem submissions, not GPU frame times.
- Seeded resource deals may assign `energy` to either homeworld; maintenance tests must account for production being added to the same vault instead of assuming a non-energy output.
- Seed-variation check: `set_layout_seed(...)`, wait two frames, compare positions, restore the original `world_config.layout_seed`.
- The default scenario sets `randomize_layout_seed = true`, so Bootstrap randomizes the layout seed and preflight planet positions differ per run; distance/preview assertions (e.g. "destination change did not alter the preview distance") can flake. Re-run before treating such a failure as a regression.
- `preflight.gd` is organized as `_constraint_*()` functions returning bool, orchestrated by `_init()`; add coverage as a new `_constraint_*()` (return false on a failed `_check`, true at the end). Constraints containing `await` are coroutines and must be awaited from `_init()`.
- Collect-mission preflight must pick an unknown **neutral** neighbor as the scout destination; an adjacent CPU homeworld is a valid scan target but rejects the collect gate (`can_dispatch_mission` requires `FACTION_NEUTRAL`), so the test flakes unless the selection filters by faction.

## Architecture constraints
- `Background` z=-100, `PlanetField` z=20; `PlanetField`/`MeteorField` must stay at local position zero (WorldConfig bounds are authored in local space, so editor offsets shift/clip the map). Background batch children inherit the background z; z-order changes can cover meteors or planets.
- Shared `WorldConfig` (Background/PlanetField/MeteorField): Bootstrap mutates only `layout_seed` (randomizes unless `ScenarioDefinition.randomize_layout_seed` is false, then applies the map's fixed seed); the background consumes `decorative_seed`. `design_size` mirrors the Godot viewport; project settings can't reference a Resource, so preflight keeps both in sync.
- Scenario selection runs in the Background root `_enter_tree()` before PlanetField enters the tree; Bootstrap `_ready()` is too late for catalog generation. `ScenarioCatalog` selects for a fresh scene; changing the catalog on a live PlanetField does not hot-swap.
- `SeededLayout._enter_tree()` must generate catalog planets before sibling `PlanetNetwork._ready()`. `planet_field.tscn` holds only static modules (NavigationField, PlanetNetwork, WorkerManager); `Planet` children are runtime catalog instances inserted before `PlanetNetwork` and must stay unowned in the editor. Only `Planet` children are laid out.
- `Planet.layout_size` derives from `Planet.size_profile` (not an enum); new profiles require updating the Resource array + IDs together. `build_slot_count` is size-driven (variable=1, large=2, XL=3); worker spawn timers exist but remain stopped until a researched worker factory is built. `starting_workers` applies only after the final size assignment. Seed variation must shuffle slots AND size/detail identity.
- `PlanetDetails` is a generic child module: `PlanetDefinition` applies its profile pre-tree, `seeded_layout` applies the final detail seed after `_ready()`; it must not finalize during `_ready()` alone. Detail cap counts logical types via `get_detail_types()` (an `asteroid_belt` is one detail despite five orbit nodes); `optional_count_range` is separate from `max_details`. Each detail references `PlanetDetailFidelity` (`full`/`throttled`/`static`); negative angular speeds are valid. Upgrade structures are `UpgradeStructure_<id>` orbit children from `add_upgrade_structure()`; their radius/phase/sprite size/tint come from `TransformerConfig` (`transformer_default.tres`), never hardcoded, and the SVGs reuse worker/meteor/navigation assets (`cluster_k/m/l`, `meteor_01..04`, `navigation_moon/comet`, `planet_satellite`).
- `GameState` (autoload `/root/GameState`) is the SSOT for ownership/factions AND resources; the Background seeds it from the active map catalog before PlanetField enters the tree. Planets must be in-tree before resolving the autoload (`apply_definition` runs during `_enter_tree`); initial workers are seeded only after layout profiles are assigned. `Planet.resolve_arrival()` owns the MVP rule: friendly adds, incoming <= defenders repels, incoming > defenders captures with survivors; ownership changes only via `GameState.faction_changed`.
- Resources are invisible, data-only `GameResource` objects from a `ResourcePool`; `GameState.deal_resources(catalog, pool, seed)` deals them seed-deterministically at game start — homeworlds get distinct resources, the rest is round-robin balanced (counts differ by at most one). No planet→resource mapping exists; maps may override the global pool via `MapDefinition.resource_pool`. Bootstrap deals after the final layout seed is set.
- Upgrade/economy state lives in `GameState` (`_planet_upgrades`, `_faction_vaults`), but GameState knows neither planet worker counts nor size profiles: the UI layer enforces `cost_workers` (`_on_buy_upgrade_pressed` passes `available_workers` into `purchase_upgrade`, then `unregister_workers`), and `Planet.generate_economy_resources()` passes `size_profile.resource_base` as `base_amount` into `generate_resources_for_planet`. The economy timer (10s) stays disabled until `worker_automation` research, while collection missions are the first neutral income path. Trait lookups in `planet.gd` always use the `DEFAULT_UPGRADE_CATALOG` const; GameState resolves via its catalog parameter. `spend_faction_resource()` refuses over-draft (false, no partial spend), so upgrade maintenance is best-effort — skipped when broke, production still added.
- Mission routing: `WorkerCluster._arrive()` calls `Planet.resolve_mission()` — military→`resolve_arrival` (attack), colony→peaceful settle of neutral planets only (`ARRIVAL_SETTLED`), cargo→reinforce own planets only (rejected otherwise), collect→known neutral scanned planets only (`ARRIVAL_COLLECTED`). The type flows `PlanetNetworkUI.selected_mission_type()` → `_dispatch_clusters` → `configure_transit`; `&"military"` defaults keep old call sites valid.
- `GameState.reset_from_catalog()` clears `_planet_upgrades` and vaults, then emits `catalog_reset`; each `Planet` clears its own `UpgradeStructure_*` children in `PlanetDetails` (remove immediately, then `queue_free()`), so resets and scenario switches cannot leave stale visuals.
- `ScenarioDefinition` owns the route rule (`default=all_planets`, `wide=neighbors_only`) and applies it to the shared WorldConfig before PlanetField enters the tree; keep scenario/map/world routing synchronized. `route_mode` constrains destination lists and stored routes.
- One Moon/Comet waypoint per layout-neighbor edge; AStar2D routes every destination through this graph, and preview + WorkerManager consume the same global-coordinate path. `NavigationField` resolves WorldConfig from its parent and must rebuild after layout changes; its route method is `find_route()` (never `get_path`).
- Transit: `WorkerManager._dispatch_clusters` packs largest-first into K=1/M=5/L=100 groups and launches all in one frame; clusters carry `source_faction`, and arrival resolves friendly/repel/capture before freeing the visual cluster (first group may capture, later groups reinforce). `PlanetNetwork` and `WorkerManager` must share the same `TransitConfig` resource identity; validation requires a capacity-one tier. Spawn tiers: XL=3/5s, L=2/7s, variable=1/10s.
- Flight duration uses only logical unit load (no speed jump at the visual tier switch). `ClusterTierDefinition.capacity` vs `display_max_units` intentionally differ (K=1/4, M=5/99); `WorkerCluster.pixel_width()` is the shared footprint helper and `TransitConfig.overlap_budget` keeps margin under the 30% overlap limit. Formation is a deterministic V/wedge with the same offsets at source and destination; clusters stay transit-only (counters, not resting sprites) and expose `Attachments` for future assets. Don't keep unused `WorkerState` values.
- `cluster_tier_bonus` is visual-only: `Planet.get_cluster_tier_bonus()` flows through `WorkerManager` into `WorkerCluster`/`Dispatch.cluster_definition()` and shifts K/M/L visuals upward without changing logical capacities, packing, arrival counts, or flight load.
- Flight time is computed in two places that must stay in sync — `PlanetNetwork._update_preview` and `WorkerManager._dispatch_clusters` — and both must pass the source planet's `get_transfer_speed_multiplier()` (multiplicative upgrade trait) or the preview diverges from actual transit.
- `PlanetNetwork` owns routing/lines and injects `UIThemeConfig` into the dynamically created `PlanetNetworkUI` (CanvasLayer); panel offsets recompute on viewport `size_changed`. `PlanetNetworkUI` content lives under `PlanetPanel/MarginContainer/PanelScroll/Content`, so hierarchy changes require updating all cached NodePaths and the panel-scroll preflight together. `StarfieldBackground` batches stars/dust via `MultiMeshInstance2D` and folds/grain via `draw_multiline()` with configurable alpha buckets; viewport resize must rebuild transforms, and `batch_texture_size` tunes shape textures, not density.
- Dynamic upgrade rows can raise `PanelContainer.get_combined_minimum_size().x` beyond the configured panel width; responsive HUD placement must use that effective width and recalculate after list rebuilds, otherwise the resource bar overlaps the panel. A single deferred call may run before Container minimum sizes settle.
- `SeededLayout._create_runtime_modules()` appends `EconomyManager` + `CpuDispatchAI` + `ShipManager` after layout; they are not in `planet_field.tscn` (which stays static-module-only). Economy/CPU expose `set_enabled(false)` plus manual `tick_now()`/`dispatch_once(true)` hooks, which preflight calls to keep the persistent suite deterministic.
- `CpuDispatchAI` picks neutral→colony, weaker own planet→cargo, enemy→military and launches via `WorkerManager.dispatch_mission()` (public wrapper over `_dispatch_clusters`); tuning lives in `CpuDispatchConfig` (`decision_interval`, `reserve_workers`, `minimum_source_workers`, `dispatch_fraction`).
- Discovery and research are per-faction state in `GameState` (`_known_planets`, `_scanned_planets`, `_researched_techs`). Own planets are always known; capture (`set_faction`) marks the new owner as knowing the planet; `discover_planet()` emits `planet_discovered` and is idempotent, while `scan_planet()` stores resource/size/build-slot intel. `research_technology()` spends vault resources, checks prerequisites and discovery gates via `TechnologyCatalog.can_research`, and emits `technology_researched`.
- Planet technologies are a separate `_planet_technologies[planet_id]` state, not global research: only an own known planet may research them, reset clears them, and `generate_resources_for_planet()` consumes their `TechnologyDefinition.production_multiplier`.
- Scout slice: `shipyard_construction` research gates the shipyard upgrade; `ShipManager.can_build_scout()` then requires the shipyard + researched `scout_hull` + `scanner_drone` + build cost, and `build_scout()` only accepts unknown layout-neighbors. `ScoutShip` flies `NavigationField.find_route()` and calls `GameState.scan_planet()` on arrival, storing resource/size/build-slot intel before freeing itself. Reuses `cluster_k.svg` as the tier-1 hull and `planet_satellite.svg` as the scanner drone.
- `TechnologyMenu` (CanvasLayer, layer 60) is created by `PlanetNetwork` after the ship manager exists; it is mutually exclusive with the planet panel (`opened` closes the planet panel, planet panel opening closes the menu). Its PLANET tab lists only `GameState.known_planets_of(PLAYER)` and renders scan intel/build slots; `worker_automation` remains hidden until the first scan, and the worker-factory node appears in the hangar only after construction. MECH techs are visible but inert until Layer 3.
- `TechnologyDefinition` entries are required to provide `visual_asset`, `effect_id`, and `mechanic_description`; the menu renders the icon/effect, while ship and planet effects have real runtime consumers. Existing cluster/planet assets are reused for the first catalog entries.
- `EventLog` is an autoload beside `GameState`: `push()` records and emits a toast, `log_silent()` records without a toast, and the default export target is `user://player.log`; scan reports, worker-factory activation and collection income are visible setting-appropriate events.

## Interaction and assets
- Planet clicks need the planet `Area2D`/shape; cluster graphics stay collision-free. The persistent destination tab UI must be created with `call_deferred()` (avoids "parent node is busy setting up children").
- `MessageFeed` replays only EventLog entries marked visible; when enforcing its toast cap, remove a child from the container before `queue_free()` because deferred freeing leaves `get_child_count()` unchanged and can turn a `while` loop into a hang.
- Cluster visuals are cell-shaded mech silhouettes (K=fighter, M=triad, L=capital) at configured sizes with an `Attachments` node; no per-unit transit sprites, no resting/idle unit assets, no cluster stacking or oversized radius rings.
- Faction distinction and strength live on the `Planet` itself: `_draw()` renders a faction ring and a runtime `StrengthLabel` (worker count) colored by `TransformerConfig.resolve_tint(&"faction", ...)` (player=blue, cpu=red, neutral=grey). The label counter-scales by `1.0 / scale.x` so text stays readable across planet size classes.
- New SVG planet/detail assets generate tracked `.svg.import` files during the headless scan; commit the import sidecars with their sources.

## Godot pitfalls
- Godot 4.7 `@export_enum` requires String/Integer-compatible variables, not `StringName`. Resource/waypoint scripts consumed by `@tool` planet/layout scripts must also be `@tool`, or editor-time generation can produce placeholders.
- `NavigationWaypoint.configure()` may run before the node enters the tree during graph rebuild; don't rely on `@onready`, and add the node before assigning its global position so PlanetField offsets aren't applied twice.
- A `MultiMeshInstance2D` requires `MultiMesh.mesh` (a `QuadMesh`) before `instance_count`; texture+transforms alone trigger the Compatibility renderer's misleading `mesh.is_null()` errors.
- Meteor sizes are pixel-based: `meteor_field.gd` converts 4-10 px targets using each SVG texture width; keep this contract instead of restoring relative scales.
- `SceneTree.quit()` doesn't halt the current function; test scripts must `return` after `quit()`. Headless `--script` runs hang when `_init` errors or returns before `quit()`; only fail via `_check`→`quit(1)` and always end with `quit()`. Keep `--quit-after 2` for the smoke test only.
- A headless run re-saves scenes in the worktree: it adds `uid=`/`unique_id=` attributes and can strip `ext_resource` references it deems redundant (a run dropped `meteor_field.tscn`'s `meteor_config` link). Check `git status` after headless runs and revert spurious scene re-saves.
- Hand-authored `.tres` files should reference scripts/assets by `path` only (no `uid=`), matching the scene files. Adding `uid=` for freshly generated `.gd.uid` sidecars logs misleading "invalid UID" warnings in headless runs and falls back to the text path anyway.
- GDScript `:=` fails inference on `Node`-typed children and preflight helper returns; use explicit types/casts (e.g. `(ocean as Node2D).global_position`). `int / int` warns `INTEGER_DIVISION`; use `int(a / 2.0)` for a float quotient.
- Connect a Tween's `finished` to a non-base-class method with `Callable(node, "_method")`; `node._method` is an unsafe member access.
- Compatibility renderer may log `Debug CanvasItem Redraw is not available yet` (benign). It is triggered by the editor's `Debug > Canvas Item Redraw` toggle sending `set_debug_redraw` to the running game — no project code or project setting causes it (verified by search); silence it via that editor menu. A cyan circle around each planet is the collision-debug overlay for `ClickArea/CollisionShape2D` (radius 120); `StarfieldBackground._ready()` force-sets `SceneTree.debug_collisions_hint = false` so the running game overrides the editor's `Debug > Visible Collision Shapes` toggle.

## Design direction
- Hybrid built in vertical slices: strategic galaxy map now, tactical battle view later. Dispatch: slider 1..available → live flight-time/route preview (more units = slower) → pack largest-first into K/M/L → launch all groups; source counter drops at launch, destination rises on arrival. Three fixed capacities for now (K=1, M=5, L=100; 7 → M+K+K). Flight-time formula stays balanced, simple, rescalable. Cell-shaded paperclip comic; mechs not implemented. Durable decisions live in `DESIGN.md`; consult it before changing dispatch, transit, or future mech layers.

## Repository
- Nested Git repo; operate from the project root. Local commit author identity may be absent; use per-command `GIT_AUTHOR_*`/`GIT_COMMITTER_*` instead of changing Git config.
- Working tree must stay free of secrets and personal machine paths (user preference). Old commits still contain `C:/Users/Vannon/…` in `DESIGN.md`, so a truly public repo needs a history rewrite; a cleaned working tree alone does not remove it.
- `.agents/` is gitignored (Freebuff/local workspace, never publish). `*.gd.uid` are legitimate Godot sidecars and belong in the repo.

## Git hooks
- `core.hooksPath` is `.githooks` (keep active): `pre-commit` runs `git diff --cached --check` plus preflight, `commit-msg` requires one explanatory sentence per staged file, and `post-commit` pushes. For an explicitly local-only commit, run both gates manually then one-shot `git -c core.hooksPath=/dev/null commit`; this leaves the hook configuration unchanged.
- `pre-commit` resolves Godot via `$GODOT_BIN`, else `godot`/`godot4` on PATH — never hardcode a machine path. `post-commit` pushes `origin HEAD:$branch`, so a commit is public immediately after it lands unless the hook is bypassed.
